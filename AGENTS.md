## Learned User Preferences
- Keep the Studio UI light and minimal; do not restyle it dark or add a Cursor UI package. Prefer one auto-detected media drop zone covering the whole composer card (prompt, mode-type row, chips, and toolbar), not Atlas-style separate image/video/audio areas. Make the prompt box resizable. Hover a mention or attached-media expand control for a small thumbnail preview, not a large scrolling lightbox.
- Never print, commit, or echo secrets (`.dev.vars`, Oxen API keys, OAuth client secrets, encryption/session keys). Prefer `pbpaste` or in-app Settings over chat.
- Do not invent a synchronous Oxen generation path; image and video stay on the async queue.
- Allowlist lives in Settings as a left-nav category with the form on the right, not as a standalone sidebar button.
- When a DS Studio slice is done, commit to `main`, push, and `wrangler deploy` to studio.digisavvy.dev with the required `--var` flags. Do not wait for a separate ship prompt. Never force-push, skip hooks, or print secrets.
- Continue existing work; do not restart the project or revert finished work.
- Local placeholder GitHub OAuth must not send users to `/login/oauth/authorize`.
- Do not set global model defaults; let each user pick preferred models and persist their settings. Settings mode defaults list the live catalog of models that support that mode (not only starred Oxen favorites); stars stay preferred and appear first, and defaults start empty until the user sets them. Do not pre-select a mode chip (including Text → Image) until the user chooses a mode or a model. Use Oxen’s live catalog and keep controls consistent across models; image models that support resolution (including Seedream 5.x) must expose those options. Models whose schema includes safety tolerance, a safety checker, or moderation must expose those controls too. Safety tolerance starts at the most permissive allowed value, the checker starts off, and moderation starts at the least restrictive value (`low`). Seedream has no safety field. Ghost unsupported mode pills for the selected model; choosing a ghosted mode resets the model.
- Site name and logo are instance settings under Settings → Branding (admins only). Unset values use “Oxen Studio” and the bundled Oxen mark. Do not hardcode DigiSavvy as the default.
- Credits control is labeled “Buy Credits”, shows a live dollar balance, and links to https://www.oxen.ai/digisavvy/settings/billing; the generate button shows live estimated cost (including resolution, count, and duration) and keeps bold keyboard-hint icons. Count always starts at 1× and resets to 1× when the model changes, so a previous 4× run cannot surprise-charge the next session.
- Support multiple generations per prompt and `@Image`/`@Video`/`@Audio` mentions for models that accept references. Mention pills stay editable (changing the number does not delete the mention) and do not rewrite when chips are reordered; reference chips are draggable with live-updating numbers. Each attachment chip shows its reference number on top (Image 1, Video 1, Audio 1) and a truncated filename below, including before a model is selected. Typing `@Image4` or `@4` should filter the mention picker to that attachment so Enter or click confirms it. Reference modes including Seedance 2.5 do not require a reference. Library items attach via a light desktop slide-in peek (prompt + thumbs, an attach button, Esc/X to close); clicking the peek image or a variation thumb opens it full size, and the main result image does the same. On mobile the library is a full-screen picker, not a cramped desktop drawer. In the media attach peek, the delete control must not cover thumbs or receive clicks while hidden—Studio × is the small corner control, and Delete + Oxen stays on the large preview. Inside a gallery, select multiple items and Attach them to the current generation in gallery order. Attach all adds the whole gallery. References the current model cannot take are skipped. Gallery tiles can be dragged into order before attaching, and that order is saved with the gallery. A gallery holds 96 items. The gallery opened from the prompt shows that full set. An open gallery accepts dropped files, library tiles, and canvas results; a drop adds the item and does not remove it if it is already in the set. Lightbox swipes follow the gesture and advance one item; a short swipe eases back, and one trackpad flick moves one image. An open gallery fills the library column and hides the past-work grid. Past work is its own screen, filtered by All, Images, Videos, or Audio. Every tile, including video and audio, can be bulk-selected for download, attach, add to gallery, or delete (Studio or Oxen). Failed items can be selected and deleted; download and add-to-gallery wait for a finished file. On a gallery tile, role, Attach, and Feature sit on one icon row so the thumbnail stays visible; the checkbox and × stay put. Character is a dark person icon, Background blue, Object brown, Style purple, Attach a teal paperclip, Feature an amber star (the first image is already featured), and Play a green triangle on video and audio. A tile already on the generation shows a dark check labeled Attached. Gallery videos show a still; the capture time is Settings → Library → Video still, seconds into the clip (default 1 second, 0–120 in half-second steps). A shorter clip uses its last moment. An existing image thumbnail is kept.
- History is a click-to-toggle slide-out on desktop and mobile, filterable by tag, and should use small generated thumbnails rather than full-size files. Tags apply to a generation group, not each output. Settings and logout live under the user avatar; do not bind Settings to Cmd+, (that opens the browser settings). Library toggles with ⌘⇧L and Settings opens with ⌘⇧,. Show those chords on the controls. Waiting states use the Blocks indicator from [loading.dev](https://loading.dev/spinners/blocks) (nine-block sweep), in the studio ink, everywhere a task is loading.

## Learned Workspace Facts
- DS Studio is a Cloudflare Workers + Vite/React app (Hono API, D1, R2) in the public repo [DigiSavvy-Inc/oxen-ai](https://github.com/DigiSavvy-Inc/oxen-ai) (MIT). Tracking issue is [DigiSavvy-Inc/oxen-ai#1](https://github.com/DigiSavvy-Inc/oxen-ai/issues/1). Self-hosters set `GITHUB_ORG`, `GITHUB_ADMINS`, and `OXEN_BILLING_URL`; an empty org means allowlist and admins only.
- Local: `npm run dev` at http://localhost:5173; local sign-in uses this machine’s `gh` login via `GH_TOKEN`. Local uploads without `PUBLIC_BASE_URL` return data URIs; production uses signed R2 media URLs via `PUBLIC_BASE_URL=https://studio.digisavvy.dev`.
- Production origin is https://studio.digisavvy.dev (Worker `oxen-studio`); users sign in with GitHub, then add their Oxen key in Settings. The Worker encrypts that key and proxies Oxen, and never exposes it to the browser after save. Production GitHub OAuth callback is only `https://studio.digisavvy.dev/api/auth/callback`; do not reuse another app’s callback or point it at `workers.dev`.
- Access is DigiSavvy-Inc org members or the D1 allowlist; bootstrap admin is `GITHUB_ADMINS=984399` (digisavvy's GitHub account id; numeric entries match ids, which survive renames). Allowlist rows bind to the GitHub account id on first sign-in.
- A project belongs to the active profile. Profiles share the account and Oxen key; library and galleries follow the active profile, and saved prompts stay on the account. Opening a project fills the composer with its prompt, reusable look, and pinned files; a run can change those without rewriting the project. Defaults store the prompt, the look (a name and text, separate from the Style reference role), files pinned from the composer, and linked galleries. Projects opens from the top bar and slides in from the right, with defaults in that panel. Expand a project for its sessions. Generate updates the open session; New session starts from the defaults. A share link lets a signed-in person generate with those defaults until it is revoked or it expires, and it does not change the owner’s project. Under the prompt, What the model receives shows the look plus the prompt, and one line per file when the model has no role inputs.
- Modes (text-to-image, image-to-image, text-to-video, reference-to-video, video-to-video) go through the Oxen async queue only; 1–4 outputs share a `batch_id` with group-level tags, and succeeded results are archived to R2 (`result_key`) then listed with fresh signed URLs. Persist only redacted media refs in D1 `params_json` (never full data URIs); D1 rejects strings over ~2MB (`SQLITE_TOOBIG`). Reference-to-video models (including Seedance 2.5) can run without a reference file. Seedance face refs stay https Studio signed URLs (`input_face_images` / `input_face_videos`) because data URIs 400 and hub file URLs time out in ByteDance’s face upload. Seedance stills are rewritten to a plain JPEG at their real pixel size before that fetch, so face upload does not measure an embedded preview. The frame is scaled only when an edge would fall outside 300–6000px or the 0.4–2.5 ratio. AVIF remains AVIF in the library. Face upload does not accept AVIF; the Seedance JPEG rewrite covers those stills, and any other provider fetch of an AVIF file receives a PNG copy. New thumbnails are PNG, WebP, or JPEG. Image refs (including Seedream) go out as signed Studio https URLs. Inlining those bytes makes Oxen rehost them as `hub.oxen.ai` playground files, and ByteDance times out downloading that URL. Video and audio still inline. Hub-only images are copied into the user’s R2 first. There is no Atlas-style `asset://` ingest—do not add a fake bypass toggle. File drops still use untrusted Studio URLs when they cannot be inlined.
- Worker unit tests use Vitest (`npm test`); CI lints, tests, and builds, and does not deploy.
- Production D1 is `oxen-studio` and R2 is `oxen-studio-media`; remote D1 has `0004_generation_tags.sql` applied; committed `wrangler.jsonc` must not include `PUBLIC_BASE_URL` or a real `GITHUB_CLIENT_ID` (those are deploy-time vars).
- Catalog should include Seedream 5.0, GPT Image 2.5, Seedance 2.5, Kling 3.0, and Wan 3.0; image models that support resolution must expose those options. `GET /api/billing/credits` returns remaining USD (or null) plus the DigiSavvy Oxen billing URL.
- Settings Cleanup can wipe this user’s Studio media from D1 and R2 (`u/{userId}/`, including uploads) and optionally delete matching Oxen playground files (`DELETE /api/repos/.../workspaces/{id}/files`). Library hover × removes from Studio; **Oxen** also deletes the hub copy. Oxen queue DELETE still only cancels in-flight jobs; succeeded queue rows are not purged.
- The Studio shell caps at 1440px and centers on wide screens. The library slides in from the left and Projects from the right. They share one width, from the screen edge through the 1440px shell gutter, and do not push layout. The scrim starts under the top bar, so the bar stays clear. The peek docks to the right. The gallery attach panel covers the media above the prompt; one tile can still be dragged onto the prompt. An open gallery fills the library column and hides the past-work grid. The top nav (Library, New, Projects, Settings, Buy Credits, avatar, profile icon) shares the composer’s 920px column. The profile switch is an icon to the right of the avatar. Mobile stays full-bleed, and the header stays pinned to the top while the page scrolls.
- Seedance reference roles are explained on the chip, the gallery role menu, and in Help. Character is a tight headshot only and goes to the face input; a full-body shot, a pose, or the room marked Character sends the wrong face. Background is the empty place. Object is a prop, a body, a pose, or an outfit, and is not a face. There is no Clothing role; a value saved as clothing is treated as Object, and the prompt says which. Style is light and color. Character images are numbered before other images, so `@Image1` is the first character image. Insert bindings writes one prompt line per chip from those numbers and does not invent names; two or more audio clips get one voice line, and a second click does not repeat a line already in the prompt.
